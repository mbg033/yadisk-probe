# yadisk-probe

Проверка того, какие файлы на Яндекс.Диске сейчас нельзя прочитать. Скрипт
`yadisk-probe.py` читает первый байт каждого файла через REST API Яндекс.Диска
и составляет список файлов, содержимое которых хранилище не возвращает.

Список файлов и их метаданные (размер, MD5, SHA256) при такой потере остаются
целы: веб-интерфейс и команда `rclone ls` показывают все файлы. Отличить доступный файл
от недоступного можно только чтением содержимого. Чтение одного байта на файл
проверяет диск на 200 тысяч файлов за несколько часов вместо скачивания всего
объёма.

## Как работает проверка

1. Скрипт получает список файлов и сохраняет его в файл `listing.json`. По
   умолчанию список составляет rclone командой `rclone lsjson -R`. С параметром
   `--lister api` список составляет сам скрипт: он обходит папки через REST API
   (`GET /v1/disk/resources`) в 16 потоков. Диск на 200 тысяч файлов rclone
   перечисляет примерно за 11 минут, REST API - примерно за 16 минут. Имена,
   которые rclone выводит закодированными (например, перевод строки как `␊`),
   скрипт переводит обратно, поэтому оба способа дают одинаковый список.
2. Для каждого файла скрипт запрашивает ссылку на скачивание
   (`GET /v1/disk/resources/download`) и читает по ней первый байт запросом
   `curl -r 0-0`.
3. Результат каждого файла дописывается в файл `results.csv` сразу после проверки,
   поэтому прерванная проверка продолжается с того же места.
4. Папки верхнего уровня с меньшим числом файлов проверяются первыми, чтобы
   итог по небольшим папкам был готов раньше итога по большим.
5. В конце скрипт пишет файлы `unavailable.txt` и `summary.txt`.

Статусы файлов:

| Статус | Значение |
|---|---|
| `OK` | первый байт прочитан |
| `UNREADABLE` | хранилище ответило `206 Partial Content` и закрыло соединение, не передав данных |
| `ERROR` | после трёх попыток не удалось получить ответ: ошибка API, тайм-аут или `HTTP 500` от хранилища |
| `EMPTY` | файл нулевого размера, проверять нечего |
| `MISSING` | Яндекс не нашёл файл по пути: файл удалён после составления списка, или в его имени есть управляющий символ |

Ответ `206` без данных повторяется при каждой новой попытке, поэтому скрипт не
повторяет её и сразу отмечает файл как `UNREADABLE`. Полное скачивание такого
файла зависает. Временные ошибки (`429` и `5xx` от API, тайм-ауты, `HTTP 500`
от хранилища) скрипт повторяет до трёх раз с паузами 5 и 10 секунд и только
затем отмечает файл как `ERROR`.

Если Яндекс отклоняет токен (`401` или `403`), скрипт останавливает проверку,
пишет отчёт по уже проверенным файлам и завершается с сообщением о том, что
требуется новый токен. Иначе каждый следующий файл получил бы ложный статус.

## Токен

Скрипт хранит OAuth-токен в файле `~/.config/yadisk-probe/token.json`, а при
заданной переменной окружения `XDG_CONFIG_HOME` - в файле
`$XDG_CONFIG_HOME/yadisk-probe/token.json`. Другой файл задаёт параметр
`--token-file`. Файл создаётся с правами `0600`, его каталог - с правами `0700`.

В файле хранятся ClientID и Client secret OAuth-приложения, токен доступа, токен
обновления и срок действия токена доступа. Когда до конца срока остаётся меньше
суток, скрипт перед проверкой продлевает токен запросом к
`https://oauth.yandex.ru/token` и записывает новый токен в тот же файл.

rclone получает токен через переменные окружения `RCLONE_YANDEX_TOKEN`,
`RCLONE_YANDEX_CLIENT_ID` и `RCLONE_YANDEX_CLIENT_SECRET` и обращается к диску
как к временному remote `:yandex:`. Настраивать remote в rclone не требуется.

## Ограничения

- Проверяется только первый байт. Файл, начало которого читается, а остальная
  часть повреждена, получает статус `OK`. Полная проверка описана в разделе
  "Полная проверка отдельных папок".
- Результат описывает состояние на момент проверки. Файл, который читался утром,
  днём может стать недоступным, и наоборот.
- Скорость ограничивает Яндекс: 10-20 файлов в секунду независимо от числа
  потоков. Диск на 200 тысяч файлов проверяется за 3-5 часов.
- Файл, в имени которого есть управляющий символ (например, перевод строки),
  получает статус `MISSING`: Яндекс показывает такой файл в списке папки, но по
  пути отвечает `404`.

## Требования

- Linux;
- Python 3.9 или новее, только стандартная библиотека;
- `curl`;
- `rclone`, если список файлов составляет rclone, то есть без параметра
  `--lister api`. Проверено на версии 1.75.1;
- учётная запись Яндекса, на которой можно создать OAuth-приложение. По
  сообщениям пользователей, Яндекс может потребовать подтвердить личность через
  Госуслуги.

## Настройка

### Почему нужно собственное OAuth-приложение

С октября 2026 года токен, полученный через встроенное OAuth-приложение rclone,
перестал давать доступ к файлам: запрос квоты (`rclone about`) проходит, а любой
запрос к файлам и папкам возвращает
`[410 - GoneError] Gone (Ресурс больше недоступен.)`
([rclone issue #10067](https://github.com/rclone/rclone/issues/10067)). С
токеном собственного OAuth-приложения доступ к файлам работает.

### 1. Создать OAuth-приложение

На странице https://oauth.yandex.ru/client/new следует создать приложение:

- платформа "Веб-сервисы". Redirect URI Яндекс подставляет сам:
  `https://oauth.yandex.ru/verification_code`. Менять его не требуется: с ним
  Яндекс показывает код подтверждения прямо на странице, и скрипт обменивает
  этот код на токен;
- права Яндекс.Диска: "Чтение всего Диска" и "Доступ к информации о Диске".

После создания приложения следует сохранить ClientID и Client secret.

### 2. Получить токен

Вход следует выполнять в обычном терминале:

```
python3 ~/dev/yadisk-probe/yadisk-probe.py --login
```

Скрипт:

1. спрашивает ClientID и Client secret. Секрет вводится без отображения и не
   попадает в историю команд;
2. выводит ссылку на страницу подтверждения доступа и открывает её в браузере.
   После нажатия "Разрешить" Яндекс показывает код подтверждения;
3. принимает код и обменивает его на токен. Код действует 10 минут;
4. записывает токен в файл токена;
5. выводит первые элементы корня диска.

Если элементы выведены без ошибки `410`, настройка завершена.

## Запуск

Отчёты пишутся в текущий каталог. Пробный запуск на 200 файлах проверяет
настройку за несколько минут, большая часть которых уходит на список файлов:

```
mkdir -p ~/yadisk-check && cd ~/yadisk-check
python3 ~/dev/yadisk-probe/yadisk-probe.py --limit 200
```

В начале скрипт выводит полный путь к каталогу отчётов и сообщает, составляет ли
он новый список файлов или читает сохранённый `listing.json`. Каталог `--dir`
создаётся автоматически. `~/yadisk-check` — каталог в домашней папке,
`./yadisk-check` — каталог внутри текущей папки: это разные пути.

При составлении списка через `--lister api` раз в 60 секунд выводятся число
найденных файлов в уже обработанных папках, число обработанных и ожидающих папок
и прошедшее время. Прогресс проверки файлов выводится с тем же интервалом:
число проверенных файлов, статусы, скорость и оставшееся время. Сообщение
появляется и во время ожидания ответа, когда ни один запрос ещё не завершился;
до первого результата оставшееся время указано как `unknown`. Итог этапа
выводится сразу. При составлении списка через rclone периодического прогресса
списка пока нет.

Полная проверка идёт несколько часов, поэтому её лучше запускать как временную
службу systemd: закрытие терминала её не прерывает.

```
systemd-run --user --unit=yadisk-probe --working-directory="$HOME/yadisk-check" \
  python3 -I ~/dev/yadisk-probe/yadisk-probe.py
```

| Действие | Команда |
|---|---|
| следить за ходом проверки | `journalctl --user -u yadisk-probe -f` |
| остановить проверку | `systemctl --user stop yadisk-probe` |

Остановленная проверка сохраняет отчёт по уже проверенным файлам.

Параметры скрипта:

| Параметр | Значение | По умолчанию |
|---|---|---|
| `--login` | получить токен, записать его в файл токена и завершиться | - |
| `--token-file` | файл токена | `~/.config/yadisk-probe/token.json` |
| `--lister` | чем составлять список файлов: `rclone` или `api` | `rclone` |
| `--dir` | каталог для списка файлов и отчётов | текущий каталог |
| `--workers` | число параллельных проверок | `64` |
| `--limit` | проверить не больше указанного числа файлов | все файлы |

## Результаты

| Файл | Содержимое |
|---|---|
| `listing.json` | список файлов с размерами и хэш-суммами из метаданных |
| `results.csv` | по строке на каждую проверку: `status`, `path`, `size`, `md5`, `reason`, `checked` |
| `unavailable.txt` | размер и путь каждого файла со статусом `UNREADABLE`, через табуляцию |
| `summary.txt` | число файлов по статусам и сводка по папкам верхнего уровня |

Файл `results.csv` только дополняется. Повторная проверка файла добавляет новую
строку, и в отчёт идёт последняя строка этого файла.

## Повторная проверка

Повторный запуск той же командой проверяет заново файлы со статусами
`UNREADABLE` и `ERROR` и пропускает файлы со статусами `OK`, `EMPTY` и
`MISSING`. Так видно, восстанавливает ли Яндекс недоступные файлы.

Повторный запуск берёт прежний файл `listing.json`. Чтобы проверить файлы,
появившиеся на диске позже, следует удалить файл `listing.json`: скрипт
составит список заново, а результаты прежних проверок останутся в файле
`results.csv`.

## Полная проверка отдельных папок

Для важной папки можно скачать все файлы и сравнить их MD5 с метаданными. Для
этого требуется remote rclone типа `yandex`, настроенный с токеном собственного
OAuth-приложения, в примере - `yadisk`:

```
rclone md5sum yadisk:Photos | sort -k2 > metadata.md5
rclone md5sum --download yadisk:Photos | sort -k2 > content.md5
diff metadata.md5 content.md5
```

Расхождение или ошибка чтения указывает на повреждённый файл. Такая проверка
скачивает весь объём папки.
